# SS-105: PUT /api/providers/:id/status - Admin Vetting & Approval

## 1. Title
SS-105: PUT /api/providers/:id/status - Admin Vetting & Approval

## 2. Context (Why)
We need an API endpoint to allow administrators to approve or reject provider profiles during the manual vetting pipeline.

## 3. Scope (What)
- Implement a `PUT /api/providers/{provider_id}/status` route inside `app/routers/providers.py`.
- Update the provider status inside the database.

## 4. Interface Contract (Inputs/Outputs/Data Shapes)
- **Path Parameter**:
  - `provider_id`: String (UUID format)
- **Request Body (JSON)**:
  ```json
  {
    "status": "string (must be 'approved' or 'rejected')"
  }
  ```
- **Success Response (200 OK)**:
  ```json
  {
    "id": "uuid-string",
    "name": "string",
    "status": "approved" // or "rejected"
  }
  ```
- **Error Responses**:
  - **400 Bad Request** (Invalid input or invalid transition):
    ```json
    { "detail": "Invalid status value" } // or "Invalid status transition"
    ```
    - Triggers if status is not 'approved' or 'rejected', if `provider_id` is not a valid UUID, or if the provider's status is already set to 'approved' or 'rejected'.
  - **401 Unauthorized**:
    ```json
    { "detail": "Missing API Key" }
    ```
    - Triggers if `X-Admin-Key` header is missing.
  - **403 Forbidden**:
    ```json
    { "detail": "Invalid API Key" }
    ```
    - Triggers if `X-Admin-Key` header value is incorrect.
  - **404 Not Found**:
    ```json
    { "detail": "Provider not found" }
    ```
    - Triggers if no provider record matches the requested UUID.

## 5. Acceptance Criteria (Testable Conditions)
- **Given** a pending provider exists and a request has a valid `X-Admin-Key` header, **when** an administrator sends a `PUT /api/providers/{provider_id}/status` request with status set to `'approved'`, **then** update the database status to `'approved'` and return status code 200 with the matching JSON details.
- **Given** a provider exists, **when** a request is made with an invalid status value like `'invalid_state'`, **then** return status code 400.
- **Given** a provider ID does not exist, **when** a PUT status request is made with a valid API key, **then** return status code 404 Not Found.
- **Given** a request has a missing or invalid `X-Admin-Key` header, **when** the endpoint runs, **then** it returns status code 401 Unauthorized or 403 Forbidden.
- **Given** a provider is already `'approved'`, **when** a request is made to change the status to `'rejected'`, **then** it returns status code 400 Bad Request (cannot transition from approved).

## 6. Constraints (Rules to Follow)
- **Route Injection:** Route handler must be added to the existing `app/routers/providers.py`.
- **Schemas:** Re-use the schemas defined in `app/schemas/provider.py`.
- **Dependency Injection:** Inject the DB session dependency using the existing `get_db` from `database.py`.
- **Admin Authorization:** Require authentication using an `X-Admin-Key` header. Compare this header to the `ADMIN_API_KEY` configuration setting (retrieved from environment variables). Return 401 if missing, 403 if mismatch.
- **Path Parameter Validation:** Validate that `provider_id` conforms to a standard UUID version 4 format. Return 400 Bad Request on failure.
- **Transition Validation:** Ensure provider status is currently `'pending_approval'`. Reject transitions from `'approved'` or `'rejected'` status with 400 Bad Request.
- **Database Safety:** DB status updates must occur in a transactional block. Rollback explicitly if database write/commit fails.
- **Error Handling:** Uncaught database/network errors must be handled by the global exception handler and return a clean 500 error.
- **Logging:** Log status change requests at INFO level: `Admin status update request for provider_id={provider_id} to status={status}`. Log success at INFO level: `Provider status updated: provider_id={provider_id}, status={status}`. Log auth/transition failures at WARNING level.

## 7. Anti-Scope (What NOT to Build)
- No user/provider session-based authentication (rely only on the shared admin API key header).
- No notification trigger (no email sent to the provider when status changes).
