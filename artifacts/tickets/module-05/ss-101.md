# SS-101: SQLAlchemy Models for Providers and Services

## 1. Title
SS-101: SQLAlchemy Models for Providers and Services

## 2. Context (Why)
We need a structured, relational database layer to persist provider profile information and their offered services, which forms the database layer of the provider onboarding slice.

## 3. Scope (What)
- Create two new SQLAlchemy model classes `Provider` and `Service` inside `models.py`.
- Define their columns, datatypes, default constraints, and relationship references.

## 4. Interface Contract (Inputs/Outputs/Data Shapes)
- **Class Provider**:
  - Table name: `providers`
  - Columns:
    - `id`: String(36), primary_key=True, default=lambda: str(uuid.uuid4())
    - `name`: String(255), nullable=False
    - `category`: String(100), nullable=False
    - `description`: Text, nullable=True
    - `hourly_rate`: Numeric(10, 2), nullable=False
    - `status`: String(50), nullable=False, default="pending_approval"
    - `created_at`: DateTime(timezone=True), default=lambda: datetime.now(timezone.utc), nullable=False
  - Relationship:
    - `services`: relationship("Service", back_populates="provider", cascade="all, delete-orphan")
- **Class Service**:
  - Table name: `services`
  - Columns:
    - `id`: String(36), primary_key=True, default=lambda: str(uuid.uuid4())
    - `provider_id`: String(36), ForeignKey("providers.id", ondelete="CASCADE"), nullable=False
    - `name`: String(255), nullable=False
    - `description`: Text, nullable=True
    - `created_at`: DateTime(timezone=True), default=lambda: datetime.now(timezone.utc), nullable=False
  - Relationship:
    - `provider`: relationship("Provider", back_populates="services")

## 5. Acceptance Criteria (Testable Conditions)
- **Given** an empty database and standard database engine, **when** `Base.metadata.create_all` is executed, **then** `providers` and `services` tables are successfully created in PostgreSQL.
- **Given** a valid provider record creation transaction, **when** it is saved to the database without a specified ID or status, **then** it defaults to a generated UUID string and status `pending_approval`.
- **Given** a provider record exists, **when** a service record is inserted referencing the provider's ID, **then** the record is successfully committed and linked.

## 6. Constraints (Rules to Follow)
- Models must be written in `models.py` using standard SQLAlchemy components imported from `sqlalchemy` and `sqlalchemy.orm`.
- Inherit from the existing `Base` class imported from `database.py`.
- Use SQLAlchemy's `Numeric` for `hourly_rate` to prevent floating-point precision loss.

## 7. Anti-Scope (What NOT to Build)
- No schema migration files (e.g., Alembic migrations are not required; tables will be auto-created on start).
- No API routers, controllers, or FastAPI path handlers.
- No user accounts or authentication links.
