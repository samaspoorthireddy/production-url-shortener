# SS-102: POST /api/providers - Create Provider Listing [AI-Ready]

## 1. Title
SS-102: POST /api/providers - Create Provider Listing

## 2. Context (Why)
We need an API endpoint to allow new providers to submit their profile details and initial service listing to start onboarding.

## 3. Scope (What)
- Create a new router module at `app/routers/providers.py`.
- Define request and response schemas using Pydantic.
- Expose a `POST /api/providers` endpoint to persist a new provider and their initial service listing.
- Import and mount the new router in `main.py`.

## 4. Interface Contract (Inputs/Outputs/Data Shapes)
- **Request Body (JSON)**:
  ```json
  {
    "name": "string (min_length=1, max_length=255)",
    "category": "string (min_length=1, max_length=100)",
    "description": "string (optional, default=null)",
    "hourly_rate": "float (must be > 0.0)",
    "service_name": "string (min_length=1, max_length=255)",
    "service_description": "string (optional, default=null)"
  }
  ```
- **Success Response (201 Created)**:
  ```json
  {
    "id": "uuid-string",
    "name": "string",
    "category": "string",
    "description": "string | null",
    "hourly_rate": 50.0,
    "status": "pending_approval",
    "created_at": "ISO 8601 string",
    "services": [
      {
        "id": "uuid-string",
        "name": "string",
        "description": "string | null"
      }
    ]
  }
  ```
- **Error Responses**:
  - **400 Bad Request** (Validation or Business errors):
    ```json
    { "detail": "error description" }
    ```
    - Triggers if `hourly_rate` is <= 0.
  - **409 Conflict** (Duplicate entry):
    ```json
    { "detail": "Provider listing already exists" }
    ```
  - **422 Unprocessable Entity** (FastAPI Pydantic schema validation errors):
    - Triggers if required string fields are empty, missing, or contain only whitespace.

## 5. Acceptance Criteria (Testable Conditions)
- **Given** a client sends a `POST /api/providers` request with a valid JSON body containing name, category, hourly rate, and service details, **when** the endpoint runs, **then** it returns status code 201 and a JSON response matching the Success contract, and saves the provider with status `pending_approval`.
- **Given** a client sends a `POST /api/providers` request with an hourly rate of `0` or negative, **when** the endpoint runs, **then** it returns status code 400 with a detailed validation message.
- **Given** a client sends a request missing required fields like `name` or `service_name` or with only whitespace, **when** the endpoint runs, **then** it returns status code 422 Unprocessable Entity.
- **Given** a client sends a request for a provider with a `name` and `category` combination that already exists in the database, **when** the endpoint runs, **then** it returns status code 409 Conflict.
- **Given** a client sends a request with script or HTML tags in string fields, **when** the endpoint runs, **then** it saves the cleaned (sanitized) strings in the database.

## 6. Constraints (Rules to Follow)
- **Route Definition:** Route handler must reside in a new file `app/routers/providers.py`. It must declare `router = APIRouter(prefix="/api/providers", tags=["providers"])`.
- **Registration:** In `main.py`, import the router and register it exactly as `app.include_router(providers.router)`.
- **Schemas:** Pydantic schemas must reside in a new file `app/schemas/provider.py`.
- **Dependency Injection:** Import path for `get_db` in the router must be exactly `from database import get_db`.
- **Input Trimming:** All input string fields must be trimmed of leading/trailing whitespace. If trimming results in an empty string for required fields, reject with 422 Unprocessable Entity.
- **Input Sanitization:** Strip any HTML/script tags from `name`, `description`, `service_name`, and `service_description` to prevent cross-site scripting (XSS) before database persistence.
- **Duplicate Checking:** Before creation, check if a provider with the exact same `name` and `category` already exists. If so, raise `HTTPException(status_code=409, detail="Provider listing already exists")`.
- **Validation for Rate:** Validation for `hourly_rate <= 0` must be handled explicitly: raise `HTTPException(status_code=400, detail="hourly_rate must be positive")` instead of letting Pydantic default to 422.
- **Database:** Handle database operations within a `db.commit()` transaction block.
- **Authentication:** No authentication is required for this public registration endpoint (conforms to Public/Guest access standard).
- **Rate Limiting:** Protect this endpoint against spam/DoS by limiting requests to 5 per minute per IP address. Return 429 Too Many Requests on breach.
- **Error Handling:** Unexpected runtime exceptions must be captured by FastAPI's global exception handler, logging the stack trace internally and returning a standard 500 error with no implementation details leaked.
- **Logging:** Log provider registration attempts at INFO level: `Provider registration started for name={name}`. Log successful creations at INFO level: `Provider registered successfully: id={provider_id}`. Log validation failures at WARNING level: `Provider registration failed: reason={reason}`.

## 7. Anti-Scope (What NOT to Build)
- No user authentication or session checks (this is a public submission endpoint).
- No admin review or status change logic (separate ticket).
- No profile image uploads or avatar URL handling.
